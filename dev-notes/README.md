# dev-notes — как устроен APT-репозиторий

## Что такое APT-репозиторий

Это просто статические файлы по HTTP, никакого серверного кода:

```
pool/main/<пакет>/<пакет>_<версия>_<arch>.deb    сами пакеты
dists/stable/main/binary-<arch>/Packages(.gz/.xz) индекс: имя, версия, зависимости,
                                                  путь к файлу и его SHA256
dists/stable/Release                              список индексов с их SHA256
dists/stable/InRelease, Release.gpg               тот же Release, подписанный
```

`apt update` скачивает `InRelease`, проверяет подпись ключом из `Signed-By:`,
потом индексы, и сверяет их хэши с `Release`. При установке хэш `.deb`
сверяется с индексом. Получается цепочка доверия от одной подписи до каждого
байта пакета. Поэтому GitHub Pages можно не доверять: подменить файл, не
сломав подпись, нельзя.

`stable` — одно имя для всех версий Debian. Это работает, потому что
бинарники собраны под glibc 2.36 и не зависят от версий библиотек конкретного
выпуска (Rust линкует всё статически, кроме libc).

## Почему ничего не хранится в git

Пакеты уже лежат в GitHub Releases исходных репозиториев. Хранить их ещё и
здесь значило бы раздувать историю git на мегабайты с каждым выпуском
навсегда. Вместо этого каждый запуск собирает репозиторий заново: скачивает
последние три выпуска каждого проекта и публикует результат как артефакт
Pages. Запуск без состояния легко повторить, и нечему разъехаться.

## Ключ без срока действия

Обычно ключам ставят срок, но здесь это ловушка. Pi обновляется без
присмотра, и когда срок истечёт, `apt update` начнёт отказывать, а заметит
это никто. Продлить срок можно, только заново разложив ключ на каждую Pi.
Компромисс: ключ без срока, а его копия хранится офлайн.

## Проверка перед публикацией

`check-repository.sh` запускает настоящий apt в отдельном каталоге: свой
`sources.list`, свои списки и кэш, через `-o Dir::...`. Скрипт падает на
любом `W:`/`E:`, то есть на битой подписи, несовпадении хэшей или
недоступном пакете. Так сломанный репозиторий не попадёт на Pages, и Pi не
останется без обновлений.
